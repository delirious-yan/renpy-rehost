## Current owner workflow — one mission, verified result (2026-10-12)

**Supersedes older per-session bootstrap/reconciliation, serial handoffs, per-phase/model "go ahead" prompts and documentation-first completion.** Start only an owner-requested task; once authorized, finish the entire bounded mission through actual implementation/output, tests, compatible fixes and necessary review without repeatedly seeking the same permission. An engineering task is not delivered through documents or review acknowledgements alone: require executed test/behavior evidence, or report the exact hard blocker. Research and routine documentation support the deliverable; review only material risk at a meaningful boundary. Protected merges, privacy, billing, customer effects and owner-PC execution still require authority that actually covers them.

**One current resume checkpoint at a material outcome/blocker, not after every step.** Source repository and actual test/PR evidence are authoritative. Owner-facing answers: **short, plain, decision-first** (normally 1–3 sentences), no long technical logs, extra dashboards or routine closing approval questions.

An owner-trusted assistant with legitimate existing private `mind-self` access may read only task-relevant portable context and reconcile material changes as a **small optional delta**. Project-only/external contributors must **not** request or be blocked by private mind-self access. Do not ask for blanket GitHub permissions when narrower available access permits the mission. Historical instructions are preserved in Git, not active workflow.

## Local continuity

Before making meaningful changes, inspect the repository for existing handoff, README, architecture, or instruction files. Do not invent project state from the mind-self summary when the current repository can be inspected directly.
